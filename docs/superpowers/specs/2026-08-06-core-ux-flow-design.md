# FootLog 핵심 UX 흐름 설계

- 작성일: 2026-08-06
- 상태: 승인됨. 2026-08-13 이후 제품 범위와 수용 기준에는 `docs/product/footlog-prd.md`를 우선 적용
- 관계: `2026-08-02-location-checkin-diary-design.md`의 후속 UX 설계
- 우선순위: PRD와 충돌하면 PRD를 우선한다. 기반 설계와 충돌하면 사용자 흐름과 MVP 범위에는 이 문서를 우선한다.

## 1. 제품 경험의 중심

FootLog의 반복 사용 중심은 **하루의 이동을 지도에서 돌아보는 경험**이다. 기록이 쌓이면 주간 단위로 반복되는 생활 반경과 새로운 영역을 객관적으로 보여준다.

제품이 사용자를 직접 평가하거나 새로운 장소 방문을 과제로 제시하지는 않는다. 사용자가 자신의 이동 패턴을 스스로 발견하도록 사실과 선택적인 회고 질문만 제공한다.

경험의 시간 축은 다음과 같다.

- 매시간: 빠르고 의식적인 위치 체크인
- 매일: 지도 중심의 하루 회고와 선택적인 일기 작성
- 매주: 반복 영역, 새로운 영역, 생활 반경 변화 확인

## 2. 정보 구조

하단 내비게이션은 세 영역으로 구성한다.

| 영역 | 역할 |
|---|---|
| 오늘 | 현재 체크인 상태, 수동 체크인, 오늘의 지도와 타임라인 |
| 캘린더 | 날짜별 체크인과 회고 탐색 |
| 발견 | 주간 이동 패턴과 개인 기준선 비교 |

설정은 `오늘` 화면 상단에서 진입한다.

## 3. 핵심 체크인 흐름

```text
정시 알림 또는 지금 체크인
  ↓
앱 실행 · 현재 위치 확인 중
  ↓
지도 핀 + 정확도 반경 표시
  ├─ 다시 찾기
  └─ 이 위치에 체크인
        ↓
     로컬 저장
        ↓
체크인 완료
  ├─ 완료
  ├─ 사진 추가
  ├─ 메모 추가
  └─ 오늘의 발자국 보기
```

### 3.1 위치 확인

- 앱이 열린 직후 받은 첫 좌표를 자동 저장하지 않는다.
- `현재 위치 확인 중` 상태를 먼저 보여준다.
- 위치가 준비되면 지도에 핀과 정확도 반경을 표시한다.
- 사용자가 `이 위치에 체크인`을 눌러야 저장한다.
- 위치가 의심스러우면 `다시 찾기`를 사용한다.
- 지도에서 핀을 수동으로 옮기는 기능은 제공하지 않는다.
- 위치 획득에 실패하면 재시도하거나 취소할 수 있다.

### 3.2 저장과 완료

- 체크인은 네트워크와 무관하게 로컬 SQLite에 먼저 저장한다.
- 성공 후 짧은 완료 피드백을 표시한다.
- 일일 회고 화면으로 강제 이동하지 않는다.
- 사용자는 바로 끝내거나 `오늘의 발자국 보기`를 선택할 수 있다.
- 활동 시간대의 마지막 체크인에서는 `오늘 하루 돌아보기`를 더 강조한다.
- 알림 없이 앱을 열어도 같은 흐름으로 현재 시각에 체크인할 수 있다.
- 놓친 시간에 대한 소급 체크인은 제공하지 않는다.

## 4. 사진과 짧은 메모

사진과 메모는 위치 저장 후 선택적으로 추가한다. 부가 기록 때문에 체크인 완료가 지연되어서는 안 된다.

### 4.1 범위

- 체크인당 사진 최대 1장
- 체크인당 짧은 메모 1개
- 사진과 메모는 모두 선택 사항
- 체크인 직후 또는 일일 회고 화면에서 추가·수정·삭제 가능
- 지도 핀이나 타임라인 항목을 선택하면 사진 썸네일과 메모 표시
- 체크인 삭제 시 연결된 사진과 메모도 함께 삭제하며 사전에 안내

### 4.2 사진 저장과 동기화

- 사진은 앱에서 압축·리사이즈한 뒤 로컬에 먼저 저장한다.
- 위치·메모 동기화와 사진 업로드를 분리한다.
- 사진 업로드 실패가 체크인 저장이나 다른 데이터 동기화를 막지 않는다.
- 서버의 객체 스토리지에 사진을 백업한다.
- 새 기기에서는 텍스트 기록을 먼저 복원하고 사진은 필요할 때 내려받는다.
- 업로드 실패 시 자동 재시도하고, 지속 실패 시 사용자가 다시 시도할 수 있다.
- 사진의 원본 EXIF 위치정보는 업로드 전에 제거한다. 위치의 기준은 FootLog 체크인 좌표뿐이다.

## 5. 일일 회고

### 5.1 지도 우선 화면

```text
날짜 · 체크인 수
오늘의 이동 지도
  - 체크인 핀
  - 시간순 연결선
  - 선택한 핀 강조
객관적인 하루 요약
시간별 타임라인
하루 회고 본문
```

- 기본 진입일은 오늘이다.
- 좌우 스와이프나 날짜 선택으로 다른 날을 탐색한다.
- 지도 핀과 타임라인 항목은 서로 선택 상태를 연동한다.
- 같은 위치의 체크인도 각각의 시간 기록으로 유지한다.
- 핀 사이의 선은 실제 이동 경로가 아니라 기록 지점을 시간순으로 연결한 선임을 명확히 표현한다.
- 알림을 놓친 시간은 부정적인 표현 없이 빈 슬롯으로 표시한다.
- 체크인이 없는 날은 빈 지도 대신 `이날은 남겨진 발자국이 없어요`와 날짜 탐색을 표시한다.
- 체크인은 삭제할 수 있지만 위치와 시각을 편집하거나 과거 위치를 새로 추가할 수는 없다.

하루 요약은 다음 사실만 제공한다.

- 체크인 개수
- 첫 체크인과 마지막 체크인 시각
- 기록 지점을 기준으로 계산한 대략적인 이동 거리
- 가장 오래 연속으로 체크인된 지도 영역

### 5.2 하루 회고 본문

- 날짜당 자유 형식의 회고 본문 하나를 작성한다.
- 작성 중인 내용은 로컬에 자동 임시 저장한다.
- 사용자가 완료해야 해당 날짜의 회고로 저장한다.
- 저장 후에도 수정하거나 삭제할 수 있다.
- 회고를 작성하지 않은 날은 빈 상태로 남는다.
- 스트릭, 작성률, 놓친 회고 경고를 제공하지 않는다.
- 회고 내용은 자동 평가하거나 주간 발견 분석에 사용하지 않는다.
- 회고 작성 후 체크인이 추가되어도 기존 본문을 변경하지 않는다.

## 6. 회고 알림

- 사용자가 선택한 경우에만 하루 한 번 예약한다.
- 초기 제안 시각은 활동 시간 종료 30분 후이다.
- 사용자는 별도 시각을 설정하거나 알림을 끌 수 있다.
- 해당 날짜에 체크인이 하나 이상 있을 때만 발송한다.
- 알림 시각 전에 그날 회고를 이미 완료하면 발송하지 않는다.
- 알림에서 회고 작성 화면으로 진입해도 사용자가 저장하기 전에는 완료된 회고가 되지 않는다.
- 알림 문구나 UI는 죄책감과 연속 작성 압박을 만들지 않는다.

## 7. 주간 발견

주간 발견은 **상단 비교 지도 → 핵심 사실 3~4개 → 선택적인 회고 질문** 순서로 구성한다.

### 7.1 데이터 축적 단계

| 기간 | 제공 정보 |
|---|---|
| 첫 주 | 체크인 수, 기록한 날짜 수, 기록된 영역, 가장 넓게 이동한 날 |
| 둘째 주부터 | 지난주와 겹치는 영역, 처음 기록된 영역, 생활 반경 증감, 요일별 이동 범위 |
| 4주 이상 | 최근 4주 개인 기준선, 평소 영역, 드문 영역, 생활 반경 변화 추세 |

`영역`은 서로 200m 이내인 체크인 지점을 하나로 묶은 공간 군집이다. `새로운 영역`은 해당 비교 기간의 이전 기록에 같은 군집이 없었던 영역을 뜻한다. 정확도 반경이 200m를 초과한 체크인은 잘못된 발견을 만들 수 있으므로 주간 영역 비교에서는 제외하되 원래의 일일 기록에는 그대로 표시한다. MVP에서는 장소명 대신 지도 영역, 거리, 비율로 표현한다. 200m 기준은 출시 후 익명화된 정확도 분포와 사용자 피드백을 근거로만 변경한다.

### 7.2 표현 원칙

- 좋음과 나쁨, 점수, 순위, 스트릭을 사용하지 않는다.
- 반복되는 생활을 부정적으로 표현하지 않는다.
- 새로운 영역을 성취 배지로 만들지 않는다.
- 새로운 장소 방문을 직접 지시하지 않는다.
- `이번 주 이동에서 기억에 남는 변화가 있었나요?`처럼 선택적인 질문만 제공한다.
- 데이터가 부족하면 억지로 비교하지 않고 언제 비교가 가능해지는지 안내한다.

## 8. 온보딩과 권한

온보딩 순서는 다음과 같다.

1. FootLog의 공간 회고 가치 소개
2. 앱 사용 중 위치 권한 요청
3. 활동 시간 설정
4. 시간별 로컬 알림 권한 요청
5. 선택적인 회고 알림과 기본 시각 제안

M1~M2에서는 로그인 없이 로컬 사용자로 온보딩한다. M3부터 카카오 로그인을 추가하고 기존 로컬 기록을 인증된 FootLog 계정에 연결한다.

- 카메라와 사진 권한은 사용자가 처음 `사진 추가`를 선택할 때만 요청한다.
- 사진 권한을 거부해도 위치 체크인과 메모는 계속 사용할 수 있다.
- 알림 권한을 거부해도 `지금 체크인`으로 기록할 수 있다.
- 백그라운드 상시 위치 권한은 요청하지 않는다.

## 9. 오류와 삭제

| 상황 | 처리 |
|---|---|
| 위치 확인 중 | 진행 상태 표시, 체크인 버튼 비활성화 |
| 정확도가 낮음 | 정확도 반경 표시, 체크인 또는 다시 찾기 선택 |
| 위치 획득 실패 | 저장하지 않고 재시도 또는 취소 |
| 오프라인 | 위치·메모·사진·회고를 로컬에 먼저 저장 |
| 사진 업로드 실패 | 체크인 유지, 사진만 별도 재시도 |
| 사진 권한 거부 | 체크인·메모 유지, 설정 이동 안내 |
| 체크인 삭제 | 연결된 사진·메모도 확인 후 삭제 |
| 회고 삭제 | 체크인 기록에는 영향 없음 |
| 계정 삭제 | 서버의 위치·사진·메모·회고를 모두 삭제하고 상태 안내 |

## 10. 아키텍처 영향

기존 모바일·Spring Boot·PostgreSQL/PostGIS 구조에 다음 경계를 추가한다.

| 단위 | 책임 |
|---|---|
| Check-in Core | 위치 확인, 사용자 확정, 로컬 저장 |
| Memory Attachment | 사진 압축·로컬 저장·업로드, 짧은 메모 관리 |
| Daily Reflection | 날짜별 지도·타임라인·회고 본문·회고 알림 |
| Weekly Discovery | 공간 군집과 기간별 객관적 비교 |
| Object Storage | 사진 파일 백업·복원·삭제 |

위치, 메모, 사진, 회고의 동기화 상태를 분리하여 한 종류의 실패가 다른 기록을 막지 않게 한다. 클라이언트 UUID 기반 멱등 upsert 원칙은 모든 텍스트 엔터티에 적용한다. 사진 업로드도 첨부 UUID를 기준으로 중복 생성되지 않아야 한다.

## 11. 개정 MVP 범위

### 포함

- 카카오 로그인과 온보딩
- 활동 시간과 정시 체크인 알림
- 현재 위치 확인 후 사용자 확정 체크인
- 로컬 우선 저장과 서버 동기화
- 체크인당 사진 1장과 짧은 메모
- 사진 서버 백업과 새 기기 복원
- 지도 우선 일일 회고와 캘린더
- 날짜별 회고 본문
- 선택적인 회고 알림
- 데이터 축적 단계에 따른 객관적 주간 발견

### 제외

- 사진 여러 장, 동영상, 음성
- 역지오코딩 장소명
- 회고 내용 자동 요약·분석
- 탐험 추천, 목표, 점수, 배지
- 소셜 공유
- 수동 핀 이동
- 백그라운드 실제 이동 경로 추적

## 12. 테스트 초점

- 위치 확인 중·성공·저정확도·실패 상태 전환
- 사용자 확정 전에는 체크인이 생성되지 않는지 검증
- 체크인 저장과 사진 업로드 실패 격리
- 오프라인 사진·메모·회고 큐와 재시도
- 사진 EXIF 위치정보 제거
- 체크인 삭제 시 첨부 정리와 회고 독립성
- 회고 알림의 사용자 시각, 비활성화, 이미 작성한 날 억제
- 첫 주·둘째 주·4주 이상 주간 발견 상태
- 지도 핀과 타임라인 선택 연동
- 새 기기에서 텍스트 우선, 사진 지연 복원
