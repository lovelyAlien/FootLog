# 체크인 확정 화면 사진·메모 통합 설계

- 작성일: 2026-08-20
- 상태: 승인됨
- 관계: `2026-08-06-core-ux-flow-design.md`의 3절(핵심 체크인 흐름)·4절(사진과 짧은 메모)을 대체하는 후속 UX 설계
- 우선순위: 이 문서와 `2026-08-06-core-ux-flow-design.md`가 충돌하면 체크인 확정 화면의 사진·메모 흐름에는 이 문서를 우선한다. 그 외 절(일일 회고, 회고 알림, 주간 발견, 온보딩과 권한, 오류와 삭제, 아키텍처 영향, MVP 범위)은 기존 문서를 그대로 따른다.

## 1. 배경

기존 설계(`2026-08-06-core-ux-flow-design.md` 3~4절)는 사진·메모를 "체크인 완료" 화면에서 위치 저장 이후에만 추가하도록 했다. 이 설계는 "위치 확인 화면에서 사진·메모까지 한 번에 처리하고 싶다"는 사용자 피드백을 반영해, 사진·메모 입력을 확정 버튼과 같은 화면으로 앞당기고 별도의 완료 화면을 없앤다.

핵심 원칙(체크인 저장은 항상 로컬에서 즉시 성공하고, 부가 기록 실패에 영향받지 않는다)은 그대로 유지한다 — 입력 시점만 앞당길 뿐, 저장 순서와 실패 격리 원칙은 바뀌지 않는다.

## 2. 새로운 체크인 흐름

```text
정시 알림 또는 지금 체크인
  ↓
앱 실행 · 현재 위치 확인 중
  ↓
지도 핀 + 정확도 반경 표시
  ├─ 다시 찾기
  ├─ 사진 추가 (선택, 라이브러리/카메라)
  ├─ 메모 작성 (선택, 최대 140자)
  └─ 이 위치에 체크인
        ↓
     체크인 로컬 저장 (항상 성공 처리)
        ↓
     (있으면) 사진 저장 → (있으면) 메모 저장
        ↓
     토스트 피드백
        ↓
     오늘 탭으로 자동 복귀
```

기존 흐름과의 차이는 "사진 추가"·"메모 작성"이 체크인 완료 이후가 아니라 위치 확인 화면 안에 함께 놓인다는 것과, 확정 후 별도의 "완료" 화면이 사라진다는 것이다.

## 3. 확정 전 화면 구성

한 화면 안에 위에서 아래로 다음 세 영역을 배치한다.

1. **위치 정보 영역** — 기존과 동일(확인 중 / 지도 핀+정확도 반경 / 실패 시 재시도)
2. **사진·메모 입력 영역(신규)** — 사진 추가 버튼(라이브러리/카메라 선택 액션시트) 또는 선택된 사진 썸네일, 메모 입력창(최대 140자, 카운터 표시)
3. **확정 버튼** — 화면 하단 고정, `이 위치에 체크인`

콘텐츠 입력 영역을 위에, 주 액션 버튼을 하단에 고정하는 배치는 Swarm·인스타그램류 게시 화면과 동일한 관례를 따른다.

**사진·메모는 위치 상태와 완전히 독립적으로 동작한다:**

- 위치가 아직 확인 중이거나 획득에 실패한 상태에서도 사진 추가·메모 작성이 가능하다.
- 사용자가 고른 사진/작성한 메모는 화면을 벗어나지 않는 한(뒤로 가기·앱 종료 제외) 컴포넌트 로컬 상태로 유지되며, 위치가 다시 확인되거나 `다시 찾기`로 재시도해도 사라지지 않는다.
- 사진·메모는 이 시점에 아직 DB에 저장되지 않는다 — `check_in_notes`/`photo_attachments`는 `check_in_id`를 참조하므로, 체크인 레코드가 먼저 존재해야 저장할 수 있다.
- 확정 버튼의 활성/비활성 여부는 기존 규칙(`위치 확인 중`에는 비활성화)을 그대로 따르며, 사진·메모 입력 여부와는 무관하다.

카메라·사진 권한 요청 시점(`사진 추가`를 처음 눌렀을 때만 요청)과 권한 거부 시 안내(설정 이동 안내, 체크인·메모는 계속 사용 가능)는 `2026-08-06-core-ux-flow-design.md` 8절·9절 그대로 유지한다.

## 4. 확정 시 저장 순서와 오류 처리

`이 위치에 체크인`을 누르면 다음 순서로 처리한다.

1. 체크인을 로컬 SQLite에 저장한다. **이 단계는 실패하지 않는 한 항상 완료 처리된다** — 사진·메모 저장 여부와 무관하다.
2. 사진을 골랐다면 방금 생성된 체크인 id로 사진을 저장한다.
3. 메모를 작성했다면 같은 체크인 id로 메모를 저장한다.

2, 3단계는 서로 독립적으로 시도한다 — 한쪽이 실패해도 다른 쪽 저장을 막지 않는다(기존 문서 10절의 "한 종류의 실패가 다른 기록을 막지 않는다" 원칙과 동일). 체크인 저장 자체가 실패하는 경우(위치 획득 실패 등 기존에 이미 있던 경로)는 이 설계의 범위 밖이며 기존 재시도 화면을 그대로 사용한다.

## 5. 완료 피드백과 화면 전환

- 별도의 "완료" 화면을 두지 않는다 — `CheckInScreen`의 `complete` 상태와 `오늘의 발자국 보기` 버튼은 제거한다.
- 체크인 저장이 끝나면 짧은 토스트/스낵바를 띄우고 오늘 탭으로 자동 복귀한다.
- 토스트 문구:
  - 사진·메모 모두 정상 저장(또는 둘 다 입력 안 함): `체크인됐어요`
  - 사진만 저장 실패: `체크인됐어요 · 사진 저장에 실패했어요, 일일 회고에서 다시 시도해주세요`
  - 메모만 저장 실패: `체크인됐어요 · 메모 저장에 실패했어요, 일일 회고에서 다시 시도해주세요`
  - 사진·메모 둘 다 저장 실패: `체크인됐어요 · 사진·메모 저장에 실패했어요, 일일 회고에서 다시 시도해주세요`
- 토스트는 정보 제공용이며 사용자의 추가 조작을 요구하지 않는다.

## 6. 확정 후 수정은 일일 회고에서만

- 확정 후에는 이 화면에서 사진·메모를 다시 볼 수 없다.
- 오늘 탭 타임라인이나 일일 회고 화면(`DailyDetailScreen`)에서 해당 체크인을 선택하면 기존과 동일한 편집 가능한 `CheckInAttachmentEditor`가 나타나 사진·메모를 추가·수정·삭제할 수 있다.
- 사진·메모 1장/1개 제한, 선택 사항 여부, 지도 핀·타임라인 선택 시 사진 썸네일·메모 노출 등 `2026-08-06-core-ux-flow-design.md` 4.1절의 범위 규정은 그대로 유지한다.

## 7. 범위

### 포함

- 확정 화면 안에서의 사진 추가(라이브러리/카메라)·메모 작성
- 확정 시 체크인·사진·메모 순차 저장과 부분 실패 시 토스트 경고
- 완료 화면 제거, 오늘 탭 자동 복귀

### 제외 (이 문서 범위 밖, 기존 문서 유지)

- 사진 서버 업로드·동기화 흐름 (4.2절, 별도 계획에서 이미 다룸)
- 일일 회고 화면의 편집 UI 자체 (6절, 기존 첨부 UI 계획을 그대로 재사용)
- 체크인 삭제 시 첨부 정리 (여전히 범위 밖)

## 8. 테스트 초점

- 위치 확인 중·실패 상태에서도 사진·메모 입력이 막히지 않는지
- `다시 찾기`로 위치를 재시도해도 이미 고른 사진·메모가 유지되는지
- 확정 시 체크인 저장이 사진·메모 저장 성공 여부와 무관하게 항상 완료 처리되는지
- 사진 저장 실패, 메모 저장 실패, 둘 다 실패하는 각 경우의 토스트 문구
- 확정 후 오늘 탭으로 정상 복귀하는지
- 확정 후 이 화면에서 사진·메모가 더 이상 보이지 않고, 일일 회고에서는 정상적으로 편집 가능한지
